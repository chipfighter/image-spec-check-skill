# 对比测试：有没有 image-spec-check，出图到用户认可各花多少

2026-10-24 做的小测试。同样的 3 张图要求，一组用 image-spec-check，一组不用，从第一次生成一直改到用户认可，比较两组漏到用户面前几处错误、用了多少 token。

**被测的是旧版本**：本目录的 `被测版本_SKILL.md`，也就是仓库标签 `test-2026-10-24` 对应的 `image-spec-check/SKILL.md`。仓库里现在的 SKILL.md 已经按这次的结果减负，减负后的版本还没有测过。

## 结果

| | 无skill | 有skill（主代理 + 4 次核对） |
|---|---|---|
| 第 1 轮漏到用户面前的问题 | 1 张 | 2 张（其中一张用户说是小问题） |
| 用户看图轮数 | 2 | 2 |
| 成功生成的图 | 7 张 | 8 张 |
| Claude token 原始合计 | 572 万 | 872 万（约 1.5 倍） |
| Claude token 按计价倍率粗算 | 约 147 万 | 约 294 万（约 2 倍） |
| Codex 输入 token（只算成功的调用） | 95 万 | 100 万 |

粗算的公式是：输入 + 1.25×缓存写入 + 0.1×缓存读取 + 5×输出。这只用来看相对多少，不是账单。完整数字、用户原话和过程中的偏差，见 [记录.md](记录.md)。

看到的情况：

- **方位**：两组 6 张图方位都对。无skill 组的提示词里也自己写了“一点透视、朝镜头走来”“不要照搬三视图的站姿”，skill 在提示词上加的规则没有拉开差距。
- **无skill 组也会自检**：长椅只转头、斜挎包背反、椅背缝里多出一只手，都是它自己发现、自己修掉的。所以这次比的是“skill 的清单加独立核对”和“模型自己检查”，不是“检查”和“不检查”。
- **核对和用户对不上**：
  - 比用户严：有三处核对判不通过，用户却认可，多走了几轮。
  - 漏掉：有一处核对判通过，用户指出了透视和反手。
- **在原图上修图会带进新问题**：补桌角时带出了透视错误，调光线时把头发和衣服的颜色也改了。

只有 3 张图、每张跑一次，生图本身随机性很大，结论只能当参考。

## 测试设计

- **任务**：`任务.md`，3 张 16:9 的图：
  - 街道：往远处延伸的老街上走路，测方位。
  - 书桌：坐着伸手拿杯子，测顺手和手指。
  - 长椅：坐着转身回头，测坐姿。
- **角色**：虚构角色，三视图在 `参考/`，两组共用。提示词在 `参考/三视图_提示词.txt`。
- **两组**：各开一个 Claude Code 子代理（Claude Opus 5.5），提示词在 `agent-prompts/`。两组互相看不到对方的文件。
  - 无skill 组：不能用 Skill 工具，按模型平时的做法写提示词、生成、交付。
  - 有skill 组：调用 image-spec-check，按 skill 流程做。Claude Code 的子代理不能再开子代理，所以 skill 要求的独立核对子代理由主代理代开（Claude Sonnet 5.5，低推理强度），模板见 `agent-prompts/核对员.md`。
- **生图**：两组都只能用 `gen.sh` 调 Codex CLI（gpt-6.1-sol，低推理强度，调用 GPT 的图片生成工具），一次只跑一张。
- **用户看图**：
  - 每轮两组都交付后，主代理把图复制成匿名的 `场景_甲.png`、`场景_乙.png`，甲、乙是随机分的，对照表在 `logs/对照.txt`。
  - 用户只凭肉眼判断，主代理把用户原话转给对应的组。
  - 改到用户认可为止，最后才揭晓哪张是哪组。
- **token 统计**：
  - Claude：按每个子代理完整对话记录里的逐次 API 调用汇总，同一条消息只算一次（`logs/sum_usage.py`）。主代理自己调度的开销两组都不算。
  - Codex：`gen.sh` 每次调用后把用量记进 `logs/codex_usage.tsv`。

## 复现或做新一轮

1. 准备 Claude Code（或别的能开子代理、能调生图工具的 agent）、Codex CLI 和 ffmpeg。把要测的 SKILL.md 装进 skills 目录。
2. 新建一个测试目录，放入 `任务.md`、`_wrap.txt`、`gen.sh`，以及转回 PNG 的 `参考/角色三视图.png`：
   ```bash
   ffmpeg -i 参考/角色三视图.webp 参考/角色三视图.png
   ```
   `gen.sh` 默认调用 PATH 里的 `codex`，可以用 `CODEX_EXE`、`CODEX_MODEL` 两个环境变量改。另外写一份 README，说明 `gen.sh` 的用法。
3. 用 `agent-prompts/` 里的两份提示词各开一个子代理，`<测试目录>` 换成实际路径。有skill 组回复 `READY_FOR_CHECK` 时，按 `核对员.md` 开核对子代理，把结论原样转回去。
4. 两组都交付后，做匿名对照给用户看，把用户原话转给对应的组，一直到用户认可。
5. 统计 token：
   ```bash
   py -I logs/sum_usage.py 无skill=<子代理记录.jsonl> 有skill=<...> 核对1=<...>
   ```
   Claude Code 的子代理记录在 `~/.claude/projects/<项目>/<会话 id>/subagents/agent-<子代理 id>.jsonl`。Codex 用量看 `logs/codex_usage.tsv`。
6. 结果和用户原话写进新一轮自己的 `记录.md`。

建议在新一轮里改进的地方：

- **多测几次**：每个场景多跑几次，或者多加几个场景，3 张图太少。
- **单独测减负后的版本**：减负后的 skill 默认不再开独立核对子代理，正好可以和这次的两组对比。
- **测一次线稿**：用户平时遇到的方位错误多出在多格线稿里，这次没测到，下一轮可以加一组 2×2 线稿。
- **核对说明不要加料**：本次第 2 轮的核对说明里多加了一句查斜挎包，详见 `agent-prompts/核对员.md`，复现时不要加。

## 文件

- `任务.md`、`_wrap.txt`、`gen.sh`：任务和生图脚本
- `agent-prompts/`：两组和核对员的提示词
- `被测版本_SKILL.md`：这次测的 skill 版本
- `参考/`：虚构角色三视图和它的提示词
- `无skill/`、`有skill/`：两组各自的图、提示词和自检局部图；有skill 组还有 `清单.md` 和 `核对记录.md`
- `记录.md`：用户每轮的原话、token 明细、过程中的偏差和结论
- `logs/`：
  - `codex_usage.tsv`：每次 Codex 调用的用量
  - `对照.txt`：匿名对照表
  - `sum_usage.py`：Claude 用量汇总脚本

为了控制仓库大小，所有图片都从 PNG 转成了 WebP（质量 90）。`清单.md`、`核对记录.md` 和提示词里写的 `.png`，对应同名的 `.webp`。匿名的 `给用户看/` 只是两组图片的复制，没有上传，哪张对应哪张见 `logs/对照.txt`。Codex 的原始日志也没有上传。
